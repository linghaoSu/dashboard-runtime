# Generated Chart Preview Security Policy

**Date:** 2026-05-09
**Roadmap Item:** ITS-ai-dashboard-builder-005
**Status:** Locked for v0.1 sandbox gate
**Owners:** Frontend platform team plus security/platform lead

## Decision

Generated chart preview must run in an isolated iframe preview host and must be bound by three checks before it can count as approval evidence:

1. iframe sandbox policy.
2. Content Security Policy.
3. `postMessage` origin, session, and widget-type validation.

Preview success is still only one input to `evaluateGeneratedChartApprovalGate`; registration also requires generated-package validation, typecheck/lint/build hook success, and human approval.

## iframe Policy

Required sandbox attributes:

```text
allow-scripts
```

Disallowed sandbox attributes:

```text
allow-same-origin
allow-forms
allow-popups
allow-top-navigation
allow-downloads
```

The preview iframe should therefore execute scripts in a unique origin. If a host uses a dedicated preview origin instead of the default unique origin, it must pass that exact origin into the preview contract and enforce it during message validation.

## CSP Policy

The default preview CSP is generated by `createGeneratedChartPreviewCsp()`:

```text
default-src 'none';
base-uri 'none';
object-src 'none';
form-action 'none';
connect-src 'none';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
font-src 'self' data:;
frame-ancestors 'self'
```

This blocks network access, forms, object/embed content, and external asset loading. Inline style is allowed because generated chart libraries often need local style injection inside the isolated preview surface. Inline script is not allowed; the host should serve or bundle the preview script from the isolated preview origin.

## Message Protocol

Every preview message must include:

- `protocolVersion: "1.0.0"`.
- `sessionId`: an opaque per-preview session token.
- `widgetType`: the generated widget type under review.
- `requestId` for render/rendered/error messages.

The parent host must validate:

- `event.origin` equals the expected preview origin.
- `sessionId` equals the current preview session.
- `widgetType` equals the widget under review.
- Message payload matches `generatedChartPreviewMessageSchema`.

Use `validateGeneratedChartPreviewMessage()` for this check. Parsing the envelope with `parseGeneratedChartPreviewMessage()` is not sufficient for approval because it does not prove the message came from the active preview.

## No-Go Conditions

- The preview iframe uses `allow-same-origin`.
- Preview CSP permits `connect-src` to product APIs or arbitrary network targets.
- The parent accepts a preview message without checking origin, session, and widget type.
- Preview output is treated as approval without hook results and human approval.
- Generated widget registration is enabled before `evaluateGeneratedChartApprovalGate()` passes.
